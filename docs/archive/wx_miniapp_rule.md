# 项目结构
- components：存放小程序的自定义组件，每个组件单独一个文件夹。
- pages：存放小程序的页面，每个页面单独一个文件夹。
- api：存放调用后端服务的文件，按模块划分，每个模块一个文件，文件命名：**Api.js。
- config：存放小程序的配置，主要是环境(dev，test，prod) 和请求的URL，默认是dev环境。
- static：存放其他常用js或者静态资源图片。

# 代码规范

## 🆕 JavaScript 语法强制约束（最高优先级）
- **严禁使用 `var`**，所有变量声明必须使用 `const`（优先）或 `let`。
- **严禁使用 `function` 关键字定义回调/箭头函数场景**，必须使用箭头函数 `=>`（除页面/组件生命周期、options 对象方法外）。
- **严禁使用字符串拼接 `+`**，必须使用模板字符串 `` `${}` ``。
- **严禁使用 `arguments` 对象**，必须使用剩余参数 `...args`。
- **严禁使用 `for...in` 遍历数组**，必须使用 `for...of`、`forEach`、`map` 等迭代方法。
- **严禁手动编写 Promise 链式调用处理异步**，必须使用 `async/await` + `try/catch`。
- **严禁使用 `==` / `!=`**，必须使用 `===` / `!==`。
- 对象/数组操作优先使用解构赋值、展开运算符 `...`、可选链 `?.`、空值合并 `??`。
- 导出统一使用 ES Module 语法（`export default` / `export const`），不使用 `module.exports`。

## 微信小程序开发规范
- 保持小程序导航使用原生导航，在 json 中配置。
- 使用微信小程序原生框架进行开发，合理使用组件化开发。
- 遵循微信小程序设计规范，确保良好的用户体验。
- 利用微信小程序提供的API进行功能开发，如登录、支付、地理位置等。
- 使用分包加载优化小程序体积和加载性能。
- 合理使用页面生命周期函数和组件生命周期函数。
- 编写详细的代码注释，并在代码中添加必要的错误处理和日志记录。
- 合理使用本地存储和缓存机制。
- 🆕 wx API 的回调形式必须封装为 Promise 或使用 `wx.promisify`，禁止嵌套回调。
- 🆕 组件 properties 必须声明类型和默认值，data 初始化必须完整。
- 🆕 页面/组件的 JS 文件顶部必须添加文件头注释，说明用途、作者、创建日期。
