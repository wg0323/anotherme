# 微信小程序开发规范

## 项目结构

- `components`：存放小程序的自定义组件，每个组件单独一个文件夹。
- `pages`：存放小程序的页面，每个页面单独一个文件夹。
- `api`：存放调用后端服务的文件，按模块划分，每个模块一个文件，文件命名：`**Api.js`。
- `config`：存放小程序的配置，主要是环境（dev、test、prod）和请求的 URL，默认是 dev 环境。
- `static`：存放其他常用 js 或者静态资源图片。

## JavaScript 语法强制约束（最高优先级）

- **严禁使用 `var`**，所有变量声明必须使用 `const`（优先）或 `let`。
- **严禁使用 `function` 关键字定义回调/箭头函数场景**，必须使用箭头函数 `=>`（除页面/组件生命周期、options 对象方法外）。
- **严禁使用字符串拼接 `+`**，必须使用模板字符串 `` `${}` ``。
- **严禁使用 `arguments` 对象**，必须使用剩余参数 `...args`。
- **严禁使用 `for...in` 遍历数组**，必须使用 `for...of`、`forEach`、`map` 等迭代方法。
- **严禁手动编写 Promise 链式调用处理异步**，必须使用 `async/await` + `try/catch`。
- **严禁使用 `==` / `!=`**，必须使用 `===` / `!==`。
- 对象/数组操作优先使用解构赋值、展开运算符 `...`、可选链 `?.`、空值合并 `??`。
- 导出统一使用 ES Module 语法（`export default` / `export const`），不使用 `module.exports`。

## 微信小程序开发规范

- 保持小程序导航使用原生导航，在 json 中配置。
- 使用微信小程序原生框架进行开发，合理使用组件化开发。
- 遵循微信小程序设计规范，确保良好的用户体验。
- 利用微信小程序提供的 API 进行功能开发，如登录、支付、地理位置等。
- 使用分包加载优化小程序体积和加载性能。
- 合理使用页面生命周期函数和组件生命周期函数。
- 编写详细的代码注释，并在代码中添加必要的错误处理和日志记录。
- 合理使用本地存储和缓存机制。
- wx API 的回调形式必须 Promise 化：基础库 2.10.2+ 异步 API 不传 success/fail/complete 时默认返回 Promise，或自行封装 / 使用 `miniprogram-api-promise`（微信无内置 `wx.promisify`），禁止嵌套回调。
- 组件 properties 必须声明类型和默认值，data 初始化必须完整。
- 页面/组件的 JS 文件顶部必须添加文件头注释，说明用途、作者、创建日期。

## 新建项目自述文件（强制）

- **文件名固定**：项目根目录 `README.md`（与 `project.config.json`、`app.json` 同级，全大写 + `.md`），禁止 `readme.md`/`README.MD`/`README_CN.md`/`项目说明.md` 等变体。
- 章节骨架、按项目类型裁剪与填写红线统一遵循 `doc-writing` 技能的 `references/readme-template.md`（唯一真相源，未安装该技能时按其骨架生成）。本栈差异项：
  - 环境要求写微信开发者工具版本 + 最低基础库版本 + AppID；
  - 快速开始写「克隆 → 微信开发者工具导入项目根目录 → 填写 AppID →（使用 npm 时）工具栏构建 npm → 编译预览」；
  - 配置说明写 `config/` 各环境 URL 与 `project.config.json` 的 appid/setting；
  - 项目结构须体现 `pages`/`components`/`api`/`config`/`static`；
  - 模板中的 `API 文档` 章节改名为 `接口地址与环境切换`，`部署指南` 改为 `上传与发布`（上传体验版 → 提交审核 → 发布）。
