# 改动分级细则

分级的唯一目的是划清**理解责任的边界**：哪些改动可以信机器，哪些必须你自己看懂才允许合并。它不替代 `test-execution` 的范围决策——测多大范围归它，本文件只回答"这一级需要哪几类信号"。

## 为什么必须先分级

AI 生成代码的风险分布极不均匀。同样是 200 行改动，风险可以差两个数量级：

- 一种是详情页三个字段的透传，写错了用户点开就看得见，回滚成本为零；
- 另一种是资金扣减与订单状态流转，写错了要人工对账。

如果不分级，你会把注意力平均分给所有代码——结果是关键的没看透，次要的看了也没用。

## 判定优先级

三条判定规则按顺序执行，先命中者生效：

1. **按业务语义判**：是否触及身份、钱、状态、数据一致性。触及即 B 级，与改动行数无关。
2. **按影响面判**：是否被多处复用，或改变跨模块 / 对外契约。公共工具、拦截器、跨模块 DTO、全局配置 key 命中即 B；局部私有 DTO 的内部字段映射不自动升级。
3. **按可控性判**：出错后不能在分钟级发现并回滚时，至少按 B 级并加强验证；只有触及主表列出的 C 类对象才归 C，不能仅凭“难以回滚”禁止 AI 修改普通代码。

## 边界判例

下列场景最容易被误判，需要先确认影响面再定级。

| 改动描述 | 表面级别 | 实际级别 | 判定理由 |
| --- | --- | --- | --- |
| 列表页加一个查询条件 | A | B | 条件里带 `user_id` 过滤即为资源归属校验，漏了就是水平越权 |
| 对外 DTO 加一个字段 | A | B | 契约变更，影响前端解析、序列化兼容、缓存中的旧结构 |
| 局部私有 DTO 加内部映射字段 | A | A | 不改变对外契约且只在单模块使用时按局部改动验收；发现其他消费方则升 B |
| 给方法加 `@Transactional` | A | B | 同类自调用不生效、异常类型决定是否回滚、传播行为影响外层 |
| 加一个定时任务 | A | B | 多实例并发触发、重入、执行失败后的补偿都要判 |
| Flyway 加一列 | B | B | 历史数据默认值、大表锁、回滚是否可逆 |
| 同步改异步 | B | B | 失败补偿、消息顺序、消费幂等全部重算 |
| 调整日志格式 | A | A | 无业务语义，出错可即时发现 |
| 改按钮颜色 / 间距 | A | A | 纯样式，视觉可即时验证 |
| 把 `if` 改成卫语句 | A | B | 若原分支含异常吞掉或状态流转，等值改写可能改变语义 |
| 换一个 JSON 库 / 升级依赖版本 | A | B | 序列化行为、空值策略、日期格式都可能变 |

## 按级别的验收动作

命令仅示意，实际参数按项目调整。跑测试的范围决策与止损纪律遵循 `test-execution` 技能。

### A 级

按 `test-execution` 选择与实际改动相符的外部信号，不固定执行 Java 命令：

- 代码改动：运行项目已有的编译、lint、类型检查或受影响模块测试；涉及架构约束时才运行架构断言。
- 纯文档改动：运行已有的 Markdown / 链接检查；未配置时复核 diff，不启动应用服务。
- 局部 DTO 内部映射：验证受影响模块与映射结果；发现对外契约或其他消费方时重新定级。

通过即可交付，不要求逐行阅读，但要求在交付证据里写明"哪些点没有看"。

### B 级

在 A 级基础上追加二选一：

```bash
# 选项一：变异测试（核心逻辑）
mvn org.pitest:pitest-maven:mutationCoverage -DtargetClasses=com.example.order.service.*
```

```text
选项二：独立审查（见 references/review-protocol.md）
输入 = diff + 需求原文 + 分级，输出 = 阻断/建议清单
```

两者都做更好，但至少做一项。只跑单测不看代码就合并 B 级改动，是本技能明确禁止的行为。

### C 级

```text
1. AI 只输出方案与脚本正文，不执行
2. 人工逐行核对：作用范围、WHERE 条件、是否可回滚、是否有备份
3. 人工在目标环境执行，执行前记录当前状态快照
```

## 三个常见错误

**按行数定级**。改一行 `if (user.getId().equals(order.getUserId()))` 就是 B 级，改三百行样式是 A 级。行数与风险无关。

**按文件所在目录定级**。`util` 目录下的小工具被十个模块引用，风险高于 `controller` 下一个没人调的接口。

**让 AI 自己定级后直接采信**。AI 倾向于把改动判轻以缩短流程。分级结论必须由你确认，并写在交付证据首行——写出来才能被追责。

## 判不准时

按 B 级处理，并把"为什么判不准"写进不确定点。多花一次审查的成本，远低于一次漏判的返工成本。
