# 独立审查协议

机械门禁只能判结构，测试只能判"你想到的路径"。剩下那部分——事务边界、并发、越权、失败路径——只能靠另一个**没有参与实现**的判断者。

## 为什么必须换一个会话

在同一个会话里让模型"再检查一遍自己刚写的代码"，它检查的是自己的**解释**，不是代码本身。它会复用写代码时的假设，把"我认为这里应该这样"当成事实。这是确认偏误，不是能力问题。

可行做法，按可靠性排序：

1. 新会话 / 另一个 IDE，只喂 diff 与需求（首选，成本最低）；
2. 换一个模型审（不同训练分布的盲区不重合，效果最好）；
3. 同一会话但明确要求"先不看你的解释，只读 diff"（最弱，聊胜于无）。

## 输入约定

给审查者的：

- `git diff` 全量输出（含工作区未提交部分）；
- 需求原文，不是实现者的转述；
- 改动分级结论与理由；
- 项目规范技能名（让它按同一套标准判）。

**不给**审查者的：

- 实现者的解释、设计取舍说明；
- 实现者的自检结论、"我已经确认没问题"；
- 交付证据里的"已修复"字样。

解释一旦进入上下文，审查者就会为已有实现找理由。这条比任何清单都重要。

审查者**只输出清单，不改代码**。让它修，它会顺手引入新问题，而且修复过程又失去监督。

## 审查清单

按 B 级改动逐条过，每条要么给出"无问题"的依据，要么给出具体位置。

| 项 | 要问的问题 |
| --- | --- |
| 资源归属 | 每个按 ID 查询或更新的入口，是否校验了当前用户对该资源的归属？漏一个就是水平越权 |
| 事务边界 | 事务方法内是否有远程调用、文件 IO、消息发送？同类自调用是否让 `@Transactional` 失效？异常类型是否触发回滚？ |
| 幂等 | 重复提交、消息重投、上游重试时，会不会重复扣款/重复插入？靠什么去重，唯一索引还是状态机？ |
| 并发 | 是否有"先查再改"的检查后使用？共享可变状态是否有锁？锁的粒度与顺序会不会死锁？ |
| 异常处理 | 有没有吞异常？内部异常信息是否直接返回给前端？捕获后是否破坏了事务回滚？ |
| 入参校验 | 边界、长度、负数、零、超大值、空集合是否覆盖？校验发生在进入业务逻辑之前还是之中？ |
| SQL | 是否全部 `#{}` 参数绑定？有没有 N+1 查询？条件字段有没有索引？有没有无条件全表更新/删除？ |
| 日志与敏感信息 | 密码、证件号、令牌、完整手机号是否进了日志？异常栈里是否带敏感参数？ |
| 契约兼容 | 字段删改、枚举新增、默认值变化，旧客户端与旧数据是否还能跑？ |
| 失败路径 | 连接、流、锁是否在异常路径释放？超时是否设置？失败后状态是否停在一个可恢复的位置？ |

## 输出格式

```text
【阻断】OrderServiceImpl.java:88
  事务方法内调用了 paymentClient.refund()，远程超时时本地事务已提交，
  但退款结果未知，会形成"钱退了、状态没改"的不一致。
  建议：退款移出事务，用状态机 + 补偿任务收敛。

【建议】OrderController.java:32
  入参未校验 pageSize 上限，理论上可传入 100000。
  建议：加 @Max(100)。

【观察】OrderMapper.xml:57
  该查询按 create_time 排序但无对应索引，数据量上去后会慢。
  当前量级影响不大，记录待观察。
```

三条判定要求，缺一不算有效问题：

1. **位置**：文件 + 行号，能直接跳过去；
2. **触发条件**：什么输入或什么时序下会出问题；
3. **影响**：出问题后用户或数据会怎样。

只写"这里可能有问题""建议优化"，属于无效审查意见，直接忽略。

## 分级标准

| 级别 | 判定 | 处理 |
| --- | --- | --- |
| 阻断 | 可复现的错误，或多用户/异常路径下的错误行为（越权、丢钱、脏数据、事务不一致） | 必须修复后才能交付 |
| 建议 | 可维护性、命名、抽象层次、防御性校验 | 记录，可延后，不阻断交付 |
| 观察 | 不确定是否为问题，需要业务知识判断 | 交给你判断，判断结果写回不确定点 |

**"建议"不能阻断交付**。否则审查会退化成风格警察，几次之后你就会跳过它。

## 误报处理

审查者看不到完整上下文，误报正常。处理方式：

- 误报 → 在清单里标注"已确认非问题 + 依据"，不要沉默略过；
- 同类误报出现两次 → 在审查提示词里补一条排除规则，而不是每次手工过滤；
- 审查者连续两轮给不出阻断级问题，而线上确实出了问题 → 说明审查清单缺项，把这次事故补进清单，而不是换一个审查者。

## 记录

审查结论进交付证据，只写结论与数量，不贴全文：

```text
【独立审查】新会话 review a1b2c3d..HEAD → 阻断 1（事务跨远程调用）、建议 2，阻断已修复并复看
```

审查清单本身也要演进：每次逃逸到线上的缺陷，都问一句"清单里为什么没有这一项"，然后补上。
