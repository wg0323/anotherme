# 代码安全规范

编写、审查或生成涉及用户交互、数据处理及资源调用的 Java 代码时必须遵守。任何违反【强制】项的代码均视为严重缺陷。

## 权限与访问控制

- **强制（水平越权）**：所有隶属于用户的资源（订单、私信、个人信息等），在查询、修改、删除前必须做归属权校验；严禁仅凭登录态即允许访问或操作他人数据。
- **强制（CSRF）**：所有表单提交、AJAX 请求必须集成 CSRF Token 验证，防止跨站请求伪造导致的数据篡改。
- **说明**：无状态 Token 认证（Token 置于请求 Header、不依赖 Cookie）天然免疫 CSRF，可免除此项。

## 输入验证与注入防御

- **强制（参数校验）**：所有用户传入参数必须严格校验，重点封堵以下攻击向量：
  - pageSize 过大 → OOM：分页大小必须设置上限。
  - 恶意 ORDER BY 字段 → 数据库慢查询/注入：排序字段必须白名单限定。
  - 未校验的重定向 URL → Open Redirect：跳转地址必须域名白名单。
  - 非法正则表达式 → ReDoS：禁止用户输入参与正则构造，或对执行时长设限。
  - 不可信数据反序列化 → RCE：禁止反序列化不可信数据。
- **强制（SQL 注入）**：严禁字符串拼接 SQL；必须使用预编译参数绑定（PreparedStatement）或 ORM 参数占位符（MyBatis 用 `#{}`，禁止 `${}`）；动态表名、字段名、排序字段必须通过 METADATA 白名单限定。
- **强制（XSS）**：向 HTML 页面输出用户数据前，必须进行安全过滤或上下文感知的转义，禁止直接输出原始用户输入。

## 数据安全与隐私保护

- **强制（脱敏）**：手机号、身份证、银行卡等敏感信息在前端展示与日志打印时必须脱敏，如手机号显示为 `158****9119`（隐藏中间 4 位）。
- **推荐（内容风控）**：发帖、评论、即时消息等 UGC 场景，应实现文本违禁词过滤与防刷机制，防止违规内容传播。

## 业务安全与资源保护

- **强制（防重放/防滥刷）**：涉及平台资源的接口（短信、邮件、下单、支付等）必须实现多重防护：
  - 频率限制（Rate Limiting）。
  - 疲劳度控制（Cooldown）。
  - 验证码/人机校验。
- **说明**：目的是防止资源被恶意消耗导致资损或骚扰用户。
