# 单元测试规范

本规范基于《阿里巴巴 Java 开发手册》提炼，编写、审查或生成 Java 单元测试代码时必须遵守。

## 核心原则（AIR & BCDE）

### AIR（宏观标准）

- **A（Automatic）全自动**：非交互式执行，禁止 `System.out` 人肉验证，必须使用断言。
- **I（Independent）独立**：用例之间绝对独立，禁止互相调用、禁止依赖执行顺序、禁止共享可变状态。
- **R（Repeatable）可重复**：不受外部环境（网络、中间件、时间）影响；外部依赖必须通过构造注入 Mock 或内存实现。

### BCDE（用例设计）

- **B（Border）边界**：覆盖循环边界、特殊取值、时间点、数据顺序等边界值。
- **C（Correct）正确**：验证正确输入产生预期结果。
- **D（Design）设计**：结合设计文档编写，保证验证逻辑与设计一致。
- **E（Error）异常**：强制测试异常流程——非法数据、异常分支、非业务允许输入。

## 构建默认跳过测试（新建工程必配）

新建 SpringBoot 工程时，必须在 `pom.xml` 的 `<properties>` 中默认跳过测试，使 `mvn compile`、`mvn package`、`mvn install` 全程自动跳过测试的编译与执行，无需每次手动传参。

```xml
<properties>
    <!-- 跳过测试编译与执行；compile/package/install 均生效 -->
    <maven.test.skip>true</maven.test.skip>
</properties>
```

- **强制**：使用 `maven.test.skip=true`（同时跳过测试的**编译**与**执行**），而非仅 `skipTests=true`（只跳过执行、仍会编译测试代码）。这样才能在 `compile` 阶段也生效。
- **目的边界**：此配置只为打包/构建提速，不降低测试要求——交付含核心业务逻辑的代码前，必须显式执行 `mvn test -Dmaven.test.skip=false` 并确认通过，禁止只写不跑。
- **说明**：需要临时运行测试时（如 CI 流水线），命令行覆盖即可，无需改动 pom：`mvn test -Dmaven.test.skip=false` 或 `mvn install -Dmaven.test.skip=false`。
- **说明**：此配置仅改变默认构建行为，不影响 `src/test` 下测试代码本身的编写与命名规范；下述规范在编写测试时仍须遵守。

## 测试命名规范

- **强制**：测试类以 `Test` 结尾。
- **强制**：测试方法使用 `should_{预期结果}_when_{条件}` 或 `test_{方法名}_{场景}` 格式。
- **强制**：测试类与被测试类包结构一致。

```
src/main/java/com/example/user/service/impl/UserServiceImpl.java
src/test/java/com/example/user/service/impl/UserServiceImplTest.java
```

## 粒度与位置（强制）

- **强制**：测试粒度至多为类级别，推荐方法级别；跨类/跨系统交互属于集成测试范畴，不在单测中验证。
- **强制**：测试代码必须位于 `src/test/java`，严禁混入业务源码目录。
- **说明**：默认编写不启动 Spring 上下文的纯单元测试（JUnit 5 + Mockito）；确需容器支持时使用切片测试（如 `@WebMvcTest`、`@DataJpaTest`），避免无差别 `@SpringBootTest` 全上下文启动。

## 测试覆盖要求

- **强制**：整体语句覆盖率 ≥ **70%**。
- **强制**：核心模块（DAO、Manager、高复用 Service）的语句覆盖率与分支覆盖率 = **100%**。
- **强制**：以下场景必须编写单元测试：
  - 复杂的业务逻辑。
  - 金额计算、状态流转。
  - 边界条件、异常分支。
  - 公共工具类方法。
- **强制**：核心业务/模块的新增代码必须同步提交对应单测；新代码导致旧测试失败时，必须同步修正。
- **强制**：单测必须在提测前完成，禁止发布后补测；设计评审阶段即确定单测范围。

## 数据与外部依赖策略

- **强制**：禁止假设数据库中已存在特定数据，禁止手动插入不符合业务规则的数据；必须通过程序或脚本动态构造合规测试数据。
- **强制**：数据清理优先使用自动回滚机制（`@Transactional` + `@Rollback`）避免脏数据；无法回滚时使用统一前后缀标识（如 `unit_test_` 前缀）便于集中清理。
- **强制**：DB、Redis、RPC 等所有外部依赖必须 Mock 或使用嵌入式替代方案（如 H2 内存数据库），确保持续集成环境可用。

## 代码可测性

- **强制**：拒绝不可测代码——代码难以测试时优先重构业务代码，而非编写扭曲的测试代码。
- **强制**：禁止以下反模式：
  - 构造方法中包含复杂逻辑。
  - 滥用全局变量和静态方法。
  - 硬编码外部依赖。
  - 多层嵌套条件语句（用卫语句、策略模式、状态模式重构）。
- **说明**：单测是开发者的核心职责，非测试人员专属；测试代码与业务代码同等重要，需持续维护；高质量单测是规避线上故障的关键防线。

## 运行测试的执行纪律

本节只管"怎么写测试"；实际运行测试（如 `mvn test -Dmaven.test.skip=false`）时的执行前预估、止损判定与卡住排查，遵循 `test-execution` 技能。
