# CSS 编码规约

> 来源：阿里巴巴前端规约 · CSS 编码规约（https://alibaba.github.io/f2e-spec/），2026-10-29 提取改写，覆盖 CSS 与 Sass/Less。编号沿用官方原文，便于对照。
> 级别：`强制` 必须遵守；`推荐` 尽量遵守；`参考` 理解并牢记。

## 编码风格

- `强制`（1.1.1）所有声明都以分号结尾，最后一条也不能省略。
- `推荐`（1.1.2）使用 2 个空格缩进，禁止 4 个空格或 Tab。
- `推荐`（1.1.3）选择器与 `{` 之间保留一个空格。
- `推荐`（1.1.4）属性名与 `:` 之间无空格，`:` 与属性值之间保留一个空格。

  ```css
  /* bad */
  .selector {
    margin-top : 10px;
    padding-left:15px;
  }

  /* good */
  .selector {
    margin-top: 10px;
    padding-left: 15px;
  }
  ```

- `推荐`（1.1.5）`>`、`+`、`~`、`||` 等组合器前后各保留一个空格：`.selector > .children`。
- `推荐`（1.1.6）`,` 分隔的属性值中，`,` 之后保留一个空格：`rgba(0, 0, 0, 0.5)`。
- `推荐`（1.1.7）注释内容与注释符之间留一个空格：`/* comment */`。
- `推荐`（1.1.8）声明块的右大括号 `}` 单独成行。
- `推荐`（1.1.9）每个属性声明单独成行，禁止同行写多条声明。
- `推荐`（1.1.10）单行代码不超过 100 个字符；`url()` 函数内与本身无法换行的属性值例外。
- `参考`（1.1.11）多个选择器写在同一规则中时，每个选择器单独成行。
- `参考`（1.1.12）声明块内只有一条声明时也写成多行。
- `参考`（1.1.13）注释行上方留一行空行，除非上一行是注释或已是块顶部。

## 选择器

- `参考`（1.2.1）组件样式优先使用 class，避免使用 id 选择器与唯一页面元素耦合，以提升复用性并减少不必要的优先级竞争。
- `参考`（1.2.2）属性选择器的值始终用双引号包裹：`input[type="text"]`。
- `参考`（1.2.3）选择器性能：用 class 而非原生标签；避免在高频组件中使用 `[class^="..."]` 这类属性选择器；每个组合选择器内的条目不超过 3 个。

## 属性与属性值

- `推荐`（1.3.1）十六进制颜色使用最短形式：`#fff` 而非 `#ffffff`。
- `推荐`（1.3.2）不要使用 `!important` 重写样式。
- `推荐`（1.3.3）十六进制值统一小写：`#fefefe`。
- `推荐`（1.3.4）长度值为 0 时省略单位：`margin-top: 0`。
- `参考`（1.3.5）保留小数点前的 0：`opacity: 0.5`。压缩工具会去掉多余的 0，保留可提升可读性与一致性；关键是全项目统一。
- `参考`（1.3.6）声明顺序按「定位 → 盒模型 → 文字排版 → 外观 → 其他」分组排列，便于扫描与维护；各分组内保持全项目一致。

  ```css
  .declaration-order {
    /* 定位 */
    position: absolute;
    top: 0;
    right: 0;
    z-index: 100;

    /* 盒模型 */
    display: block;
    width: 100px;
    height: 100px;
    border: 1px solid #e5e5e5;

    /* 排版 */
    font: normal 13px "Helvetica Neue", sans-serif;
    line-height: 1.5;
    color: #333;

    /* 外观 */
    background-color: #f5f5f5;

    /* 其他 */
    opacity: 1;
  }
  ```

- `参考`（1.3.7）只在需要设置全部或大多数值时才用简写属性；只改单个方向时写具体属性。

  ```css
  /* bad */
  .selector {
    margin: 0 0 10px;
  }

  /* good */
  .selector {
    margin-bottom: 10px;
  }
  ```

## 其他

- `推荐`（1.4.1）不要使用 `@import`，它会加长关键渲染路径的深度；统一用 `<link>` 引入样式。

## Sass 与 Less

- `参考` 按项目需求选择原生 CSS、PostCSS、Sass 或 Less。PostCSS 是插件平台，并非 Sass/Less 的等价替代品；评估时考虑所需能力、插件维护状况与迁移成本。
- `推荐`（2.1）四则运算符两侧各保留一个空格；Sass 除法先通过 `@use 'sass:math';` 引入模块，再写 `math.div($default-width, 2)`，不使用已弃用的 `/` 除法。
- `推荐`（2.2）Mixin 名称与 `()` 之间无空格；多个参数时 `,` 前无空格、之后保留一个空格：`.size(30px, 20px)`、`.clearfix()`。
- `推荐`（2.3）Sass 按「`@use` / `@forward` → 变量声明 → 样式声明」组织文件，不使用已弃用的 Sass `@import`；Less 可继续使用其 `@import`。
- `推荐`（2.4）块内顺序：标准属性声明 → mixin 调用 → 嵌套子级选择器（放块末尾，上方留一空行）。
- `推荐`（2.5）嵌套选择器深度不超过 3 层，过深会与 HTML 结构强耦合且优先级过高。
- `推荐`（2.6）可以使用 `//` 单行注释，但要注意编译成 CSS 后会被删除；需要保留的注释用 `/* */`。
- `推荐`（2.7）用 Mixin 复用代码以符合 DRY；避免 `@extend`，它不够直观且在嵌套、加载顺序变化时存在风险。
