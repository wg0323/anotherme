# JavaScript 编码规约

> 来源：阿里巴巴前端规约 · JavaScript 编码规约（https://alibaba.github.io/f2e-spec/），2026-10-29 提取改写，语言版本 ES6+。
> 级别：`强制` 必须遵守；`推荐` 尽量遵守；`参考` 理解并牢记。
> 编号沿用官方原文；TypeScript 项目缺失的部分同样适用本文件。

## 一、编码风格

### 缩进与分号

- `强制`（1.1.1）使用 2 个空格缩进，禁止 4 个空格或 Tab。
- `强制`（1.2.1）每条语句以分号结尾。省略分号会触发 ASI 的怪异行为，例如 `const luke = {}` 后紧跟 `[luke, leia].forEach(...)` 会直接抛 `ReferenceError`。

### 逗号

- `强制`（1.3.1）多行结构不使用行首逗号。
- `强制`（1.3.2）多行结构始终保留最后一个逗号，便于增删行与生成清晰的 diff；数组、对象、参数和调用中的扩展运算符元素可以保留尾逗号，但 rest 元素或 rest 参数后不能加逗号。

### 块与大括号

- `推荐`（1.4.1）始终使用大括号包裹代码块。单行语句省略大括号看似简洁，但极易因后续追加行而产生逻辑错误。
- `强制`（1.4.2.1）非空代码块使用 Egyptian Brackets：`{` 前不换行，`}` 前换行；`}` 后接 `else` / `catch` / `while` 时不换行，结束整个语句时换行。
- `参考`（1.4.2.2）空代码块可直接写作 `{}`，但在 `if..else..`、`try..catch..` 等多块结构中仍按上条换行。
- `强制`（1.4.3）禁止空代码块；确需保留时在块内写明注释说明原因。

### 空格

- `强制`（1.5.1）空格风格：
  - 块左大括号 `{` 前有空格：`function test() {`
  - 控制语句左小括号 `(` 前有空格：`if (isJedi) {`
  - 函数名与参数列表之间无空格：`function fight() {`
  - 小括号、方括号内部两侧无空格：`bar(foo)`、`foo[0]`
  - 大括号内部两侧有空格：`{ clark: 'kent' }`
  - 运算符两侧有空格，一元运算符与操作数间无空格：`const x = y + 5`、`!y`
  - 对象字面量的 `key: value` 之间有且只有一个空格，禁止“水平对齐”：
  
    ```js
    // bad
    const bad = {
      a:            'short',
      looooongname: 'long',
    };

    // good
    const good = {
      a: 'short',
      looooongname: 'long',
    };
    ```

### 空行与行宽

- `推荐`（1.6.1）文件末尾保留且仅保留一个换行符。
- `强制`（1.6.2）代码块的开始与结束不能是空行。
- `参考`（1.6.3）块结束与新语句之间插入一个空行。
- `推荐`（1.7.1）单行不超过 100 字符；字符串/模板字符串与正则表达式例外。
- `参考`（1.7.2）单文件不超过 1000 行；`参考`（1.7.3）单函数不超过 80 行，超出应拆分。

## 二、变量

- `强制`（2.1.1）用 `const` / `let` 声明，禁止 `var`，禁止不加声明产生全局变量。
- `强制`（2.1.2）优先 `const`，仅在会被重新赋值时用 `let`。数组/对象的引用不变，修改内部成员仍用 `const`。

  ```js
  // bad
  let arr = [];
  arr[0] = 'foo';

  // good
  const arr = [];
  arr.push('foo');
  ```

- `强制`（2.1.3）一条声明语句只声明一个变量，便于追加与单步调试。
- `强制`（2.1.4）声明的变量与参数必须被使用，纯赋值不算使用。
- `强制`（2.1.5）禁止在声明前使用变量。
- `参考`（2.1.6）哪里使用、哪里声明，不要统一堆在块开头。
- `强制`（2.1.7）变量不得与外层作用域已存在的变量同名（no-shadow）。
- `强制`（2.1.8）禁止重复声明变量或函数，包括与函数参数重名。
- `强制`（2.1.9）禁止连续赋值 `let a = b = c = 1;`，未声明变量会泄漏成全局变量。
- `参考`（2.1.10）`let` 与 `const` 分别归类书写。

## 三、原始类型与字符串

- `强制`（2.2.1）禁止 `new Number()` / `new String()` / `new Boolean()`，包装对象会使 `typeof` 变成 `object` 且恒为真值。
- `推荐`（2.2.2）类型转换：数字用 `Number(x)` 或 `parseInt(x, 10)`；字符串用 `String(x)`；布尔值用 `!!x`。
- `推荐`（2.2.3）`parseInt()` 必须带基数，避免历史环境按 8 进制解析。
- `强制`（2.2.4）条件语句中禁止多余的布尔转换：写 `if (foo)` 而非 `if (!!foo)`。
- `强制`（2.2.5.1）字符串优先单引号；模板字符串仅在有变量插值或换行时使用。
- `推荐`（2.2.5.2）用模板字符串替代 `+` 拼接。
- `强制`（2.2.5.3）禁止不必要的转义字符。

## 四、数组与对象

- `强制`（2.3.1）用字面量创建数组，禁止 `new Array()` / `Array()`；仅构造指定长度空数组时用 `new Array(500)`。
- `强制`（2.3.2）`map`、`filter`、`from`、`every`、`find`、`findIndex`、`reduce`、`reduceRight`、`some`、`sort` 的回调必须 `return`。只做遍历时用 `forEach`，不要误用 `map`。

  ```js
  // bad - reduce 回调缺少 return，抛 Cannot set property of undefined
  const myObj = myArray.reduce((memo, item, index) => {
    memo[item] = index;
  }, {});

  // good
  const myObj = myArray.reduce((memo, item, index) => {
    memo[item] = index;
    return memo;
  }, {});
  ```

- `推荐`（2.3.3）用扩展运算符处理数组：复制 `[...arr]`、拼接 `[1, 2, ...arr]`、替代 `apply`、去重 `[...new Set(arr)]`；遍历可迭代对象时用 `Array.from(foo, bar)` 以免创建临时数组。
- `推荐`（2.3.4）用解构获取数组元素；函数返回多个值时用对象解构而不是数组解构。
- `强制`（2.4.1）用字面量创建对象，禁止 `new Object()`。
- `强制`（2.4.2）使用属性与方法的简写语法。

  ```js
  // bad
  const atom = {
    value: value,
    addValue: function (value) {
      return value + ' added';
    },
  };

  // good
  const atom = {
    value,
    addValue(value) {
      return value + ' added';
    },
  };
  ```

- `参考`（2.4.3）简写属性集中书写，置于对象起始或末尾。
- `强制`（2.4.4）属性名不加引号，除非包含 `-`、空格等特殊字符。
- `强制`（2.4.5）优先用 `.` 访问属性，`[]` 仅用于动态属性名与特殊字符属性名。
- `推荐`（2.4.6）用扩展运算符做对象浅拷贝与排除属性，替代 `Object.assign`：

  ```js
  const copy = { ...original, c: 3 };
  const { a, ...noA } = copy;
  ```

- `推荐`（2.4.7）用解构获取对象属性，优先在函数参数中解构。
- `参考`（2.4.8）动态属性名直接写在对象字面量中：`{ [getKey('foo')]: 'foo' }`。
- `强制`（2.4.9）禁止直接在对象上调用 `hasOwnProperty`、`propertyIsEnumerable`、`isPrototypeOf`，这些方法可能被覆盖；现代运行时优先用 `Object.hasOwn(obj, 'foo')`，兼容旧环境时用 `Object.prototype.hasOwnProperty.call(obj, 'foo')`。

## 五、函数与类

- `强制`（2.5.1）禁止 `new Function()` 创建函数，等价于 `eval`，存在注入风险。
- `强制`（2.5.2）禁止在 `if` / `while` 等非函数块中使用函数声明。
- `参考`（2.5.3）用函数表达式或箭头函数替代函数声明，避免声明提升导致的“先调用后定义”。
- `强制`（2.5.4）用箭头函数替代匿名回调。
- `推荐`（2.5.5）箭头函数风格：函数体只有一条 `return` 时可省略大括号与 `return`；返回对象或多行内容时用小括号包裹；只有一个参数且使用简写语法时可省略参数括号。
- `强制`（2.5.6）参数不得命名为 `arguments`。
- `强制`（2.5.7）禁止使用 `arguments` 对象，改用剩余参数 `...args`（它是真正的数组）。
- `推荐`（2.5.8）用默认参数语法，不要在函数体内用 `a = a || 0` 兜底（会把 `false`、`0`、`''` 误替换）。
- `推荐`（2.5.9）有默认值的参数放在参数列表最后。
- `推荐`（2.5.10）不要修改函数参数：不修改引用类型的入参，不给参数重新赋值。
- `强制`（2.5.11）IIFE 用小括号包裹。
- `参考`（2.5.12）函数圈复杂度不超过 10，认知复杂度不超过 15。
- `参考`（2.5.13）参数不宜过多，超过时用对象传参。
- `强制`（2.5.14）generator 函数内必须有 `yield`。
- `参考`（2.5.15）优先用高阶函数迭代：`map` / `filter` / `reduce` / `some` / `find`，对象用 `Object.keys` / `values` / `entries`，减少裸 `for` 循环。
- `推荐`（2.6.1）用 `class` 语句声明类，不用 prototype。
- `推荐`（2.6.2）用 `extends` 实现继承。
- `强制`（2.6.3）避免多余 constructor：空的 constructor 或只调 `super()` 的 constructor 应删除。
- `强制`（2.6.4）正确使用 `super`：子类 constructor 中必须调用 `super()` 且先于 `this`；非子类不得调用 `super()`。
- `强制`（2.6.5）禁止重复的类成员命名。

## 六、模块

- `推荐`（2.7.1）新项目优先使用 ES modules（`import` / `export`）；既有 CommonJS 项目保持模块格式一致，禁止 AMD、CMD。
- `强制`（2.7.2）禁止用多条 `import` 引入同一模块。
- `强制`（2.7.3）`import` 语句放在模块最上方。
- `强制`（2.7.4）`default import` 的名字不得与文件内其他 `export` 命名相同。
- `强制`（2.7.5）禁止模块引用自身。
- `强制`（2.7.6）禁止循环引用。
- `推荐`（2.7.7）不要在 `default export` 上用已导出的名称作属性，应具名导入。
- `推荐`（2.7.8）`import` 语句块之后保留一个空行。
- `参考`（2.7.9）`import` 排序：先第三方、后本工程；先绝对路径、后相对路径。
- `参考`（2.7.10）模块内只有一个导出时用 `export default`。
- `参考`（2.7.11）不要在 `import` 时直接 `export`。
- `参考`（2.7.12）ESM/CJS 按项目 `package.json`、构建工具与部署环境选择；浏览器和 Node.js 都可使用 ESM，仅在确有双端消费需求时提供双模块产物。

## 七、操作符与控制语句

- `推荐`（2.8.1）使用严格相等 `===` / `!==`；类型不同时先显式转换再比较。
- `强制`（2.8.2）禁止 `++` / `--`（`for` 循环条件中除外），用 `num += 1` 替代。
- `强制`（2.8.3）禁止 `void` 运算符，写 `undefined`。
- `强制`（2.8.4）禁止嵌套三元表达式，拆成独立变量。
- `强制`（2.8.5）避免多余的三元表达式：`a ? a : b` 写 `a || b`，`c ? true : false` 写 `!!c`。
- `强制`（2.8.6）混合使用多种操作符时用小括号分组，四则运算可省略。
- `强制`（2.9.1）`switch` 的每个 `case` 以 `break` 结尾。
- `推荐`（2.9.2）`switch` 始终包含 `default`；有意省略时在末尾注释 `// no default`。
- `参考`（2.9.3）`switch` 至少 3 个条件分支，更少时用 `if`。
- `参考`（2.9.4）控制语句嵌套不超过 4 级。
- `强制`（2.9.5）`for` 循环的计数器必须朝终止条件方向移动，防止死循环。
- `推荐`（2.9.6）`for-in` 循环中用 `Object.hasOwn()` 过滤原型链属性；兼容旧环境时用 `Object.prototype.hasOwnProperty.call()`。
- `参考`（2.9.7）`if` 分支都以 `return` 结尾时，省略最后的 `else`。
- `参考`（2.9.8）条件表达式遵循 ToBoolean：`{}`、`[]` 为真；`0`、`NaN`、`''`、`null`、`undefined` 为假；`'0'` 为真。

## 八、其他禁用项

- `强制`（2.10.1）禁止 `eval`。
- `强制`（2.10.2）禁止 `debugger`。
- `推荐`（2.10.3）禁止 `alert` / `confirm` / `prompt`，改用自定义弹窗组件。
- `推荐`（2.10.4）生产环境禁止 `console`；需要保留时封装一层按环境判断。
- `强制`（2.10.5）禁止对原生对象或只读全局对象赋值（`window`、`Object`、`undefined` 等）。

## 九、注释

- `推荐`（3.1）单行注释用 `//`，单独写在被注释对象上方而非行尾；注释行上方留一个空行（位于块顶部时不留）。
- `推荐`（3.2）多行注释用 `/** ... */`，不要连续多行 `//`。
- `强制`（3.3）注释内容与注释符之间有一个空格。
- `参考`（3.4）用 `// FIXME: 问题是什么` 与 `// TODO: 还要做什么` 标记待办，并对标记负责、及时处理。
- `参考`（3.5）函数、类、文件等文档类注释遵循 jsdoc 规范。
- `参考`（3.6）无用的注释代码即时删除，交给版本控制系统保管。

## 十、命名

- `参考`（4.1）文件名小写，用 `-` 连接：`hello-world.js`（部分操作系统大小写不敏感）。
- `参考`（4.2）原始类型、对象、函数、实例用小驼峰 camelCase，禁止下划线命名。
- `强制`（4.3）类与构造函数用大驼峰 PascalCase。
- `参考`（4.4）全大写下划线风格仅用于 `export` 的 `const` 常量；文件内常量与导出对象的属性键仍用小驼峰。
- `参考`（4.5）模块导出命名：函数用小驼峰；class、函数库、字面量对象用大驼峰。
- `参考`（4.6）命名不以下划线开头或结尾；类中真正的私有成员使用 `#field` / `#method()` 等私有元素，不用下划线模拟私有。

## 十一、ES5 遗留项目补充

仅维护明确不支持 ES6 的旧项目时适用；新项目禁止套用本节，尤其不得因此使用 `var` 或禁用尾逗号。

- `推荐`（5.1）用 `var` 声明，注意其函数作用域与声明提升特性，不要在声明前使用。
- `强制`（5.2）多行结构**不要**加最后一行逗号，IE6/7 与 ES3 实现会出错（与 1.3.2 相反）。
- `参考`（5.3）用 `Array.prototype.slice` 复制数组与转换类数组。
- `推荐`（5.4）不用保留字作对象属性名（IE8 不工作）。
