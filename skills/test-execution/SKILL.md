# 测试执行规范

## 第一步：先定测试范围

1. **先量全量成本，再决定是否选择**：全量（编译 + 单测 + 冒烟）≤ 5 分钟就每次全量，不引入任何选择机制；5～30 分钟按分级选择；> 30 分钟才考虑把影响面推导自动化。
2. **按变更影响面分级定范围**：L0 仅文档/注释 → 编译；L1 模块内业务逻辑 → 该模块单测 + 所在主流程冒烟；L2 公共组件/工具/拦截器/DB 结构/API 契约/MQ 消息体/配置项/依赖版本 → 全量冒烟 + 受影响模块单测 + 契约相关集成测试；L3 鉴权/核心交易/消息可靠性/发版 → 全量回归。
3. **共享代码按最大影响面定级**：改动 3 行工具类、1 个配置 key、1 个 DTO 一律算 L2，不按改动行数定级。
4. **影响面必须有推导依据**：代码引用（谁调用改动的符号）、数据链路（表/字段 → Mapper → Service → 接口）、契约链路（API/消息/配置 → 消费方）；禁止凭"我觉得改的是这块"。
5. **推导不出就升级（fail-safe）**：找不到对应测试、动态 SQL/反射/配置驱动分支、框架与依赖升级、说不清影响面 —— 直接跑全量。选择机制只允许"多跑"，不允许"少跑"。
6. **冒烟集是固定资产**：5±2 条核心用户旅程（进门 → 主流程闭环 → 落库/消息副作用），每条要有自动化入口、预期产物、成功判据、耗时上限；新增核心功能同步补一条，只增不减。
7. **周期性全量兜底**：距上次全量全绿 ≥ 2 周或 ≥ 10 次改动、发生 L3 变更、子集失败修复后、依赖大版本升级、发版前，必须跑全量。
8. **逃逸缺陷必须回流**：事后才发现的回归，24 小时内补一条冒烟或一条单测，同一个回归不允许逃逸第二次。

## 核心铁律

1. 执行前先定义预期，三条缺一不可：① 预估耗时量级与超时上限；② 关键产物（日志关键字、报告文件、退出码、状态变化）；③ 成功判据。没有预期就无法判断"未达预期"。
2. 执行测试/验证命令必须设置明确超时上限（一般为预估耗时的 2 倍以上；首次运行含编译/依赖下载/初始化须单独高估）。禁止无超时运行，禁止用"一直等着看"代替止损判定。
3. 触发任一止损信号（时间红线、静默红线、异常迹象）时，立即终止进程并转入排查；禁止"再等一会看看"。
4. 止损后先读现场再行动：检查已产出的部分输出、测试报告目录、进程/端口状态、依赖服务状态；禁止不读失败现场直接重跑。
5. 排查范围收敛：单测试方法 → 单测试类 → 模块 → 全量，逐级扩大；依赖服务类问题先修环境再复跑。
6. 退出码不等于验证通过：必须核对关键产物（Tests run 统计、关键日志、状态变化）；测试被跳过（Tests run: 0、@Disabled、skip）退出码同样为 0，不算通过。
7. 等待期间禁止空转：不得反复轮询无输出命令或无意义 sleep；应检查阶段性产物（报告文件、日志文件）或诊断进程状态。
8. 收尾必清理：给出最终答复前，终止本次启动的应用服务进程并清理临时脚本、日志等自产产物，确认端口已释放；数据库、消息队列、缓存等中间件不停，自动化测试数据按框架回滚或清理，手工运行式验证的诊断数据保留供复查，并在答复中写明状态。只清本次自产对象，禁止按映像名批量终止；用户明确要求保留的服务，须写明端口与停止方式。

## 止损信号速查

| 信号 | 判定 | 动作 |
| ---- | ---- | ---- |
| 时间红线 | 超过预估上限仍无预期产物 | 立即终止 |
| 静默红线 | 连续约 30~60 秒无新输出，且非长计算任务 | 先查进程状态（CPU/端口），异常即终止 |
| 异常迹象 | 明确执行失败，或持续重试、连接拒绝、超时超过预设阈值且无恢复进展 | 立即终止；单次 retry 和 `Errors: 0` 等统计行不触发止损 |

## "没输出 / 没结果"速查

| 现象 | 常见原因 | 先检查 |
| ---- | -------- | ------ |
| 秒退且无输出 | 参数错误、异常被吞 | 退出码、stderr、日志文件 |
| 长时间无输出 | 等待输入、依赖服务不可达重试、死锁 | 进程 CPU、依赖端口、stdin |
| 有输出但无预期日志 | 日志级别不够、输出缓冲、未重新编译 | 产物时间戳、缓冲参数 |
