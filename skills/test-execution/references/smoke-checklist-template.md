# 冒烟清单模板

冒烟集是回归测试的固定成本：每轮迭代都要跑，只增不减。本文件给出通用表头与判定规则，不绑定具体业务；落地时把示例行替换成项目真实的旅程。

第一行仅为填写示例，落地时必须替换为本项目的真实旅程。

## 字段定义

| 字段 | 要求 |
| --- | --- |
| ID | `SMK-` 加两位序号，删除后不复用编号 |
| 核心旅程 | 一句用户视角的动作描述，写"谁做了什么、看到什么"，不写技术步骤 |
| 覆盖功能面 | 这条旅程实际覆盖的模块或横切关注点，便于失败时定位影响面 |
| 自动化入口 | 可重复执行的命令或脚本路径；禁止"人工打开页面点一遍" |
| 预期产物 | 运行后会留下的客观痕迹：响应码、响应字段、数据库记录、队列消息、生成文件、日志关键字 |
| 成功判据 | 可判定真假的断言组合；至少包含一个业务结果，不能只写"无报错" |
| 耗时上限 | 单条上限，超出即视为异常并中止（防挂起） |
| 引入来源 | 初始建立 / 新增功能 / 逃逸缺陷回流（注明缺陷简述或链接） |

## 构成配方（5±2 条）

| 位置 | 覆盖内容 | 判定是否合格 |
| --- | --- | --- |
| 入口 | 登录或鉴权，取得可用的会话/令牌 | 后续旅程依赖它，必须先通过 |
| 主干 1 | 核心写操作：创建或提交 | 写入后能查到，形成闭环 |
| 主干 2 | 核心读操作：查询、列表、详情 | 返回内容与写入一致 |
| 副作用 | 数据落库、消息投递与消费、缓存更新、外部调用 | 断言外部状态，而非只看接口返回 |
| 边界（可选） | 一条高频异常路径：未登录访问、非法参数、重复提交 | 断言错误码与数据未被污染 |

取舍规则：宁可 5 条覆盖三段链路，不要 15 条挤在同一段链路里。冒烟目标是"系统整体还活着"，不是"功能测全"。

## 判定规则

| 结果 | 判定 |
| --- | --- |
| 通过 | 全部判据成立，且产物时间戳为本轮 |
| 失败 | 任一判据不成立；不得以"重跑一次就好了"直接结案，需判断是否为环境问题并记录 |
| 不算通过 | 命令退出码为 0 但未产生预期产物；用例被跳过；只启动了服务未验证业务 |
| 阻塞 | 入口旅程失败时，后续旅程标为阻塞而非通过，不能跳过后当作通过 |

## 维护规则

- **只增不减**：删除或改写判据等同于放弃防线路由，需说明理由并记录。
- **跟功能同步**：新增核心功能时补一条；核心链路重构时同步更新对应旅程。
- **缺陷回流**：任何事后才发现的回归，24 小时内补一条到这里，`引入来源` 填缺陷简述。
- **耗时复核**：每季度看一次每条的实际耗时，超过上限一倍就排查原因（依赖变慢、断言变重、数据未清理）。
- **禁止纯手工**：手工执行无法重复、无法计时、无法留痕，退化成"点两下看着正常"。

## 执行顺序与预算

1. 入口旅程先跑，失败即中止，避免在无效状态下浪费后续时间。
2. 主干与副作用按依赖顺序串行；互不依赖的可并行。
3. 全清单预算控制在 5 分钟内；超过说明单条判据过重，应拆分或移到集成测试。

## 与范围决策的衔接

- 冒烟集在 L1 及以上每轮必跑；L0 可跳过。
- 冒烟失败一律升级为全量，不进入"先修了再说"的路径。
- 范围分级与全量触发条件见 `regression-scope.md`。
