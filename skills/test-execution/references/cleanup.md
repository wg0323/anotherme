# 收尾清理

## 执行时机

- 任务收尾、给出最终答复之前执行，与"验证通过"同等对待，不等用户提醒。
- 止损终止后同样适用：「终止进程」不等于「清理完毕」，须确认应用服务端口已释放、临时产物已处理。
- 多轮会话中用户明确要求继续使用的，保留并在答复中写明端口、PID 与停止方式。

## 清理顺序

1. **采集证据**：测试统计、关键日志、退出码、状态变化——先下结论，再删现场。
2. **停止应用服务**：按 PID 终止进程树，不按映像名；中间件不停。
3. **确认释放**：应用服务端口重新查一次，无监听才算停干净。
4. **清理文件**：临时脚本、临时日志、临时文件与目录。
5. **答复中交代**：停了什么、删了什么、保留了什么及原因。

## Windows 命令速查

```bat
:: 端口反查 PID
netstat -ano | findstr :8080

:: 核对进程身份（确认命令行确为本次启动）
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'ProcessId=1234' | Select-Object ProcessId,Name,CommandLine | Format-List"

:: 终止进程树
taskkill /PID 1234 /T /F

:: 确认已退出
tasklist /FI "PID eq 1234"
```

## 归属判定（防误杀）

- 首选启动时记录的 PID；未记录时用端口反查。
- 终止前核对命令行：可执行文件与参数须与本次启动一致。命令行读不到、或明显属于其他程序（IDE、数据库、用户自己的服务）时不动手，改为报告用户。
- **禁止** `taskkill /IM java.exe /F`、`taskkill /IM node.exe /F` 这类按映像名批量终止：会连带杀掉用户其他服务与 IDE 语言服务器，事故等级远高于端口冲突。
- 端口被占但占用者不是本次会话启动的：不杀，说明占用 PID 与进程名，由用户决定。

## 清理清单

| 对象 | 处理 |
| ---- | ---- |
| 本次启动的应用服务/脚本进程及其子进程 | 终止并确认端口释放 |
| 本次启动的数据库、消息队列、缓存等中间件 | 不停，在答复中写明端口与运行状态 |
| 本次编写的临时脚本（`.bat`/`.ps1`/`.sh`/`.py`/`.sql`） | 删除；已沉淀为项目正式脚本的保留并说明 |
| 本次产生的日志与后台重定向输出文件 | 证据采集完毕后删除 |
| 本次生成的临时目录、下载/导出的临时文件 | 删除 |
| 本次写入的测试数据（表/队列/缓存键） | 自动化测试按框架回滚或清理；手工运行式验证的诊断数据保留供复查，会污染下次运行时提示用户 |
| `target/`、`node_modules/`、`dist/` 等构建产物 | 保留，不属临时产物 |
| 用户既有文件、用户启动的进程 | 一律不动 |

## 常见错误

- 把中间件当临时服务停掉，影响用户其他项目与下次验证。
- 只关终端窗口，后台子进程继续占用端口，下次启动报冲突。
- 先删日志再写结论，导致失败现场无据可查。
- 端口冲突时不查归属直接杀占用者，误杀用户正在运行的程序。
- 清理范围扩散到用户文件或项目构建产物，把"自产自清"做成"大扫除"。
- 保留了服务却不在答复中说明，用户下次启动时才发现端口被占。
