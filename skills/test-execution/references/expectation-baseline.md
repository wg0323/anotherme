# 执行前预期基线

## 执行前必答三问

动手运行任何测试/验证前，先明确（可写入执行计划或直接声明）：

1. **预估耗时**：量级是多少（秒级 / 分钟级 / 十分钟级）？超时上限定多少？
2. **关键产物**：运行过程中会出现什么、结束后留下什么？（日志关键字、报告文件、退出码、数据库/队列状态变化）
3. **成功判据**：看到什么才算通过？只写"退出码为 0"不合格。

模板：

```text
预计耗时：约 20 秒（冷启动另计）   超时上限：60 秒
关键产物：控制台 "Tests run: N" 统计行 + 新的 surefire 报告文件
成功判据：Tests run > 0 且 Failures = 0、Errors = 0
```

## 典型基线参考

| 验证类型 | 典型耗时 | 关键产物 | 成功判据 |
| -------- | -------- | -------- | -------- |
| 单元测试（单类/单方法） | 秒级~十几秒 | 测试报告、Tests run 统计 | Tests run > 0 且失败/错误为 0 |
| 集成测试（Spring 上下文/容器/Testcontainers） | 十几秒~分钟级 | 启动日志、测试报告 | 上下文启动成功 + 测试统计达标 |
| 应用启动验证 | 秒级~分钟级 | 启动完成日志、端口监听 | 关键日志出现 + 端口探测可连（禁止固定 sleep 代替探测） |
| 消息消费/异步任务验证 | 取决于业务与重试配置 | 消费者日志、队列长度/数据状态 | 可观的状态变化（禁止"等固定时长后假定成功"） |
| 构建验证（mvn package / npm build 等） | 缓存后分钟级；首次含依赖下载可达十分钟级 | 构建产物、BUILD SUCCESS | 产物文件生成且时间戳为本轮 |
| 脚本/自定义验证命令 | 按被调逻辑 | 输出、退出码、生成文件 | 脚本约定的成功标志 |

**冷/热启动差异**：首次运行含依赖下载、编译、初始化，耗时可数倍于后续；不能用首次耗时当后续预期，也不要用后续基线低估首次。

## 超时上限取值原则

- 默认取预估耗时的 2 倍以上，给足合理余量防误杀。
- 冷启动场景单独高估，预估里必须包含编译/下载/初始化时间。
- 终止后若排查确认"仅耗时低估、无真实故障"，可调高上限重跑一次，并说明本次为何预计更久；调高必须有依据，不能无限加码。
- 任何情况下都要有上限；绝对禁止无超时运行测试与验证命令。
