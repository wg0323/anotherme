# 止损与排查

## 止损判定细则

| 信号 | 细则 |
| ---- | ---- |
| 时间红线 | 已到超时上限仍无预期产物 → 终止。终止前先扫一眼已产出的部分输出，确认不是"产物就在眼前" |
| 静默红线 | 连续约 30~60 秒无新输出 → 先检查进程状态：CPU 持续高位（纯计算任务）可结合预估酌情等待；CPU 低且无进展、或在反复等待连接/输入 → 终止 |
| 异常迹象 | 明确执行失败，或持续重试、连接拒绝、超时、同一 WARN 刷屏超过预设阈值且无恢复进展 → 终止；单次 retry、`Errors: 0` 等统计行不触发止损 |

**核心理念：停止不是失败，是排查的起点。** 盲等十分钟换来的通常还是失败，而停止后排查一分钟往往就能定位根因——无输出的等待几乎不产生价值。

## 停止后的动作（按顺序）

1. **终止进程**：连同子进程一起终止；确认端口已释放、无残留进程——残留进程会污染下一次运行（端口占用、旧服务行为错乱）。
2. **先读现场（重跑之前必做）**：
   - 已产出的部分输出（stdout / stderr）
   - 测试报告目录（如 `target/surefire-reports/`、junit xml、`.pytest_cache`）
   - 日志文件（应用日志、构建日志）
   - 进程 / 端口状态、依赖服务状态
3. **按现象对照定位**（见下表）。
4. **范围收敛复跑**：单测试方法 → 单测试类 → 模块 → 全量；每级扩大前确认有明确的复现理由，不要直接回到全量。

## 常见"没输出 / 没结果"原因对照表

| 现象 | 常见原因 | 先检查 | 对策 |
| ---- | -------- | ------ | ---- |
| 秒退且无输出 | 参数错误、异常被吞、路径不对 | 退出码、stderr、日志文件 | 打开日志、加 -v / --debug |
| 长时间无输出，进程存活 CPU 低 | 等待标准输入（read/Scanner/交互性确认） | 是否在等 stdin | 非交互参数（--yes / -y / --batch）或重定向 stdin |
| 长时间无输出，伴随连接类输出 | 依赖服务未启动（DB/MQ/Redis 等），连接超时反复重试 | 依赖端口是否监听 | 先启动依赖服务，再复跑 |
| 长时间无输出，CPU 空转 | 死循环、死锁 | CPU 占用、线程 dump | 终止并 debug 定位 |
| 有进程但终端完全不见日志 | 输出缓冲（管道/重定向时常见） | 是否被缓冲 | Python 加 -u；直读报告/日志文件而非盯终端 |
| 有输出但无预期日志 | 日志级别不够；代码未重新编译（加载的还是旧产物） | 产物 class/文件时间戳、日志级别配置 | 重新编译、调整日志级别 |
| 跑完构建成功但无实质验证 | 测试被跳过（Tests run: 0、@Disabled、skip）或断言数为 0 | 测试统计行 | 核对"运行数 > 0 且通过"，而非只看 BUILD SUCCESS |
| 与上次行为不一致 | 上次残留进程/端口未释放，或此次未重新构建 | 端口占用、产物时间戳 | 清理残留进程后全量重新构建复跑 |

## 管道与退出码陷阱

- `命令 | tail` 等管道：退出码取管道最后一个命令的；判断成败要用 `PIPESTATUS`（bash）或分开执行。
- 后台运行（输出重定向到文件）：判断依据是文件内容与进程状态，终端"没动静"不代表程序没跑。
- 交互性确认（git / npm 等）：未加非交互参数会静默等待输入，表现为"卡住"，属典型静默红线场景。
