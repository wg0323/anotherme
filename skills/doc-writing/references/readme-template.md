# README.md 模板（唯一真相源）

新建项目/工程交付自述文件时必须遵循本文件。`springboot-spec`、`uniapp-spec`、`wx-miniapp-spec` 等技能内嵌的只是本文件的章节骨架摘要，措辞有出入时以本文件为准。

## 一、命名与位置（硬规则）

- 文件名固定 `README.md`，位于工程根目录，全大写 + `.md` 后缀。
- 禁止变体：`readme.md`、`README.MD`、`Readme.md`、`README_CN.md`、`readme.txt`、`项目说明.md`、`关于本项目.md`。
- 多模块（monorepo）仓库只在根目录写一份 README，子模块不重复编写，子模块差异在根 README 的「快速开始」中分小节说明。
- 编码 UTF-8，换行符 LF，语言以中文为主，技术专有名词保留英文。

## 二、章节骨架（顺序固定）

| 序号 | 章节标题                 | 性质         | 内容要求                                                                       |
| ---- | ------------------------ | ------------ | ------------------------------------------------------------------------------ |
| 1    | `# 项目名称`             | 必备         | H1 项目名，紧随其后用引用块 `>` 写一句话描述（做什么、解决什么问题）            |
| 2    | `## 📋 目录`             | 必备         | 无序列表锚点链接，与实际保留的章节一一对应                                     |
| 3    | `## 项目简介`            | 必备         | 项目背景 + 核心功能；含 `### 核心功能`，用 `- [x]` 已实现、`- [ ]`（规划中）    |
| 4    | `## 技术栈`              | 必备         | 表格：分类 \| 技术 \| 版本，写实际使用版本                                     |
| 5    | `## 项目结构`            | 必备         | 树形目录（代码块标 `text`），每个目录后用 `#` 注释一句职责                     |
| 6    | `## 环境要求`            | 必备         | 运行时、构建工具、中间件的版本清单及其他前置条件                               |
| 7    | `## 快速开始`            | 必备         | 按模块分 `###` 小节，命令可直接复制执行                                        |
| 8    | `## 配置说明`            | 必备         | 表格：配置项 \| 说明 \| 默认值，只列需要改动的关键项                           |
| 9    | `## 部署指南`            | 按类型裁剪   | 打包、部署、发布流程；小程序项目改名为 `## 上传与发布`                         |
| 10   | `## API 文档`            | 按类型裁剪   | 在线文档访问地址；无在线文档的前端/小程序项目改名为 `## 接口地址与环境切换`     |
| 11   | `## 常见问题`            | 按类型裁剪   | Q/A 形式，只写真实遇到过的问题                                                 |
| 12   | `## 更新日志`            | 条件章节     | 仅当仓库确有 `CHANGELOG.md` 时保留，否则整节删除                               |
| 13   | `## 许可证`              | 条件章节     | 仅当仓库确有 `LICENSE` 时保留，否则整节删除                                    |

## 四、按项目类型裁剪

| 项目类型                | 省略内容                       | 章节改名                                       | 必填差异项                                                                                                                       |
| ----------------------- | ------------------------------ | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 纯后端工程（SpringBoot） | 「快速开始」的前端/小程序小节   | -                                              | 环境要求写 JDK/Maven/MySQL/Redis 实际版本；快速开始按「导入 SQL → 改 `application-dev.yml` → `mvn spring-boot:run`」；API 文档写实际 `doc.html` 地址并说明生产环境关闭方式；部署指南写 `mvn package` + `java -jar` 与日志路径 |
| uni-app 项目            | 「API 文档」                    | `API 文档` → `接口地址与环境切换`               | 环境要求写 Node + HBuilderX 或 CLI + 微信开发者工具版本；快速开始写 `pnpm install` → `pnpm dev:h5` / `pnpm dev:mp-weixin`（注明用微信开发者工具导入 `dist/dev/mp-weixin`）；配置说明写 `manifest.json` 的 appid 与 `config/` 各环境接口地址；项目结构体现分包划分与主包 ≤2MB |
| 微信小程序              | 「API 文档」                    | `API 文档` → `接口地址与环境切换`；`部署指南` → `上传与发布` | 环境要求写微信开发者工具版本 + 最低基础库版本 + AppID；快速开始写「导入项目根目录 → 填写 AppID →（用 npm 时）构建 npm → 编译预览」；配置说明写 `config/` 各环境 URL 与 `project.config.json` 的 appid/setting；项目结构体现 `pages`/`components`/`api`/`config`/`static` |
| monorepo 根 README      | -                              | -                                              | 项目结构列出全部模块；快速开始按 `### 后端启动` / `### 前端启动` / `### uni-app / 小程序` 分小节；技术栈表合并列出各端 |

## 五、填写红线

- 禁止空章节：无实质内容的章节整节删除，禁止写「待补充」「TODO」「暂无」「xxx」占位。
- 禁止悬空链接：`更新日志`/`许可证` 指向的文件不存在时整节删除，不得留下死链；同理禁止引用不存在的图片与文档。
- 目录锚点同步：增删章节后必须同步更新 `## 📋 目录` 列表，锚点与实际标题一致。
- 命令可执行：`快速开始` 的每条命令必须能在该工程直接复制执行，端口、路径、文件名与工程实际一致，禁止照抄模板示例值。
- 版本写实：技术栈与环境要求写到实际使用的小版本系列（如 `3.2.x`、`8.0`、`18+`），禁止 `latest`、`最新版`、`x.x` 等含糊写法。
- 代码块标注语言：所有代码块必须标语言类型（`bash`、`text`、`yaml` 等），禁止裸代码块。
- 唯一 emoji：全文仅 `## 📋 目录` 一处标题带 emoji，其余标题不加 emoji 与装饰性符号。
- 只写事实：禁止「本项目非常优秀」「值得学习」等主观评价与营销话术。

## 六、单模块与 monorepo

- 单模块项目：直接用第三节的完整模板，删掉与本模块无关的小节（如纯后端工程删掉「前端启动」「uni-app / 小程序」）。
- monorepo（前后端 + 小程序同仓）：沿用同一骨架，「项目结构」列出所有模块目录，「快速开始」按端分小节，「技术栈」表格合并列出各端技术，子模块不再单独写 README。
