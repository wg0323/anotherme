# 界面保真自检清单

> 交付前执行通用项和当前项目适用的条件项。适用项不通过即返工，不适用项标记“不适用”，不要为通过检查引入项目没有的技术或交互。
> 标注【PC】、【移动端】、【vue-pure-admin】的条目只在对应场景执行。

## A. 结构骨架

- [ ] **已完整读过基线页**（当前前端基线文件第 2 节列出的文件），不是只看片段。
- [ ] 【PC】页面顶部搜索区、中部表格区、工具栏按钮的位置与基准页一致。
- [ ] 【PC 列表页】搜索、工具栏、批量操作、行操作和分页按基准页及业务需求保留；业务不适用的功能不强行添加。
- [ ] 【移动端列表页】列表项、加载状态、空态及导航结构与基准页一致。
- [ ] 有弹窗时，弹窗宽度、表单项排列方式、底部按钮顺序与基准页一致。
- [ ] 【vue-pure-admin】`defineOptions({ name })` 已填写且与路由 name 一致。

> 判定方式：把新页面和基准页并排打开，遮住内容只看布局轮廓，两者应该能重合。

## B. 颜色与主题

- [ ] 全局搜索本次改动文件，**没有十六进制色值**（`#` 开头的颜色）。
- [ ] 使用 Tailwind 时，**没有默认色板**：`bg-white`、`bg-gray-*`、`text-gray-*`、`border-slate-*` 等。
- [ ] 颜色只来自基线文件第 3 节的白名单，包括允许使用的 `var(--el-*)` 变量也已逐项登记。
- [ ] 项目支持暗色主题时，切换后没有刺眼的纯白块或看不清的深色文字。

> 判定方式：点右上角主题切换按钮，切到暗色再看一遍。新页面若出现一块明显比其他页面亮的白色区域，基本就是写死了颜色。

## C. 组件复用

- [ ] 【PC】表格使用基线登记的模板封装组件；模板封装了表格时，不绕过它使用裸 `el-table`。
- [ ] 【vue-pure-admin】表格外层使用 `PureTableBar`，没有自己搭标题栏。
- [ ] 弹窗、分页、业务卡片等使用基线文件第 4 节列出的适用组件。
- [ ] 没有引入新的第三方 UI 库、CSS 框架、动画库。

> 判定方式：看 `package.json` 有没有新增依赖；看模板里有没有出现基线白名单之外的组件名。

## D. 图标

- [ ] 图标走统一渲染方式（如 `useRenderIcon`）。
- [ ] 图标来自模板已有的图标集，没有安装新图标库。
- [ ] 图标尺寸、颜色与相邻页面一致，没有大小不一。
- [ ] 没有用 emoji 或图片代替图标。

## E. 样式写法

- [ ] Vue 单文件组件的局部样式只写在 `<style scoped>` 内，没有误用裸 `<style>`。
- [ ] 覆盖组件内部样式时用了 `:deep()`，并注释了原因。
- [ ] 没有 `!important` 堆叠。
- [ ] 没有未经用户明确批准的全局 `.el-*` 修改；批准项已记录在差异说明中。
- [ ] 使用 Tailwind 时，原子类语法与项目版本匹配（Tailwind 4 的 important 写在末尾：`w-45!`，不是 `!w-45`）。
- [ ] 项目提供自定义布局工具类时优先复用（如 `flex-c` / `flex-bc`），没有重复手写一长串 flex 类。

## F. 交互与状态

- [ ] 列表或表格有 loading 态，按钮请求期间有 loading 或禁用。
- [ ] 空数据时有占位，不是一片空白。
- [ ] 删除类操作有二次确认（如 `el-popconfirm`）。
- [ ] 项目使用服务端分页、排序或筛选时，条件变化后会重新请求，不是只改本地数据。
- [ ] 窄屏下不出现横向滚动条或元素重叠（有响应式判断的模板需验证）。

## G. 工程校验

- [ ] 项目配置 lint 时已在前端代码目录运行并通过；仅检查实际启用的 ESLint、Stylelint、Prettier 等工具。
- [ ] 项目配置类型检查时已运行并通过（如 `pnpm typecheck`），没有用 `any` 兜底掩盖问题。
- [ ] 没有遗留 `console.log`、注释掉的旧代码、调试用的假数据。

## H. 差异说明（必须向用户输出）

交付时用一行说明本次与基准页的结构差异：

```
与基准页的结构差异：无
```

或

```
与基准页的结构差异：
1. 增加右侧统计卡片区 —— 需求要求展示汇总数据
2. 表格去掉批量操作 —— 该业务无批量操作场景
```

**任何一条差异都要能被需求解释**。解释不了的差异就是跑偏，应当改回基准页写法。

## 给非前端的 5 秒快速验收

不用读代码，只看四处：

1. **颜色**：页面上有没有突兀的纯白块或纯灰块。
2. **间距**：各功能区域之间的空隙是否和同类页面一样松紧。
3. **按钮**：长相、圆角、大小是否和别的页面一致，有没有出现“另一个系统”的按钮。
4. **列表**：PC 检查表格工具栏、分页和列设置；移动端检查列表项、加载状态、空态和导航是否符合基准页。

四处都对，基本就没跑偏。
