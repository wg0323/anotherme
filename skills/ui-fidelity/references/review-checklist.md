# 界面保真自检清单

> 交付前逐项过一遍。任一项不通过即返工，不要以“功能已经能跑”为由跳过。
> 每项都写了判定方式，前端经验不多也能查。

## A. 结构骨架

- [ ] **已完整读过基线页**（仓库根 `docs/ui-baseline.md` 第 2 节列出的文件），不是只看片段。
- [ ] 页面顶部搜索区、中部表格区、工具栏按钮的位置与基准页一致。
- [ ] 列表页具备：搜索表单、工具栏按钮区、批量操作条（多选时出现）、行操作列、分页。缺一项即不合格。
- [ ] 弹窗宽度、表单项排列方式、底部按钮顺序与基准页一致。
- [ ] `defineOptions({ name })` 已填写且与路由 name 一致。

> 判定方式：把新页面和基准页并排打开，遮住内容只看布局轮廓，两者应该能重合。

## B. 颜色与主题

- [ ] 全局搜索本次改动文件，**没有十六进制色值**（`#` 开头的颜色）。
- [ ] **没有 Tailwind 默认色板**：`bg-white`、`bg-gray-*`、`text-gray-*`、`border-slate-*` 等。
- [ ] 颜色只来自基线文件第 3 节的白名单，或 `var(--el-*)` 变量。
- [ ] 切换暗色主题后，页面上没有刺眼的纯白块或看不清的深色文字。

> 判定方式：点右上角主题切换按钮，切到暗色再看一遍。新页面若出现一块明显比其他页面亮的白色区域，基本就是写死了颜色。

## C. 组件复用

- [ ] 表格用的是模板封装组件（如 `pure-table`），不是裸 `el-table`。
- [ ] 表格外层有工具栏封装（如 `PureTableBar`），没有自己搭标题栏。
- [ ] 弹窗、分页、业务卡片使用的是基线文件第 4 节列出的组件。
- [ ] 没有引入新的第三方 UI 库、CSS 框架、动画库。

> 判定方式：看 `package.json` 有没有新增依赖；看模板里有没有出现基线白名单之外的组件名。

## D. 图标

- [ ] 图标走统一渲染方式（如 `useRenderIcon`）。
- [ ] 图标来自模板已有的图标集，没有安装新图标库。
- [ ] 图标尺寸、颜色与相邻页面一致，没有大小不一。
- [ ] 没有用 emoji 或图片代替图标。

## E. 样式写法

- [ ] 样式只写在 `<style scoped>` 内，没有裸 `<style>`。
- [ ] 覆盖组件内部样式时用了 `:deep()`，并注释了原因。
- [ ] 没有 `!important` 堆叠。
- [ ] 没有全局修改 `.el-*` 内部类。
- [ ] 原子类语法与项目 Tailwind 版本匹配（Tailwind 4 的 important 写在末尾：`w-45!`，不是 `!w-45`）。
- [ ] 布局优先用了项目自定义工具类（如 `flex-c` / `flex-bc`），没有重复手写一长串 flex 类。

## F. 交互与状态

- [ ] 表格有 loading 态，按钮请求期间有 loading 或禁用。
- [ ] 空数据时有占位，不是一片空白。
- [ ] 删除类操作有二次确认（如 `el-popconfirm`）。
- [ ] 分页、排序、筛选变化后会重新请求，不是只改本地数据。
- [ ] 窄屏下不出现横向滚动条或元素重叠（有响应式判断的模板需验证）。

## G. 工程校验

- [ ] 在前端代码目录运行 lint 命令（如 `pnpm lint`）并通过，包括 stylelint 的属性排序与 prettier 格式。
- [ ] 类型检查通过（如 `pnpm typecheck`），没有 `any` 兜底掩盖问题。
- [ ] 没有遗留 `console.log`、注释掉的旧代码、调试用的假数据。

## H. 差异说明（必须向用户输出）

交付时用一行说明本次与基准页的结构差异：

```
与基准页的结构差异：无
```

或

```
与基准页的结构差异：
1. 增加右侧统计卡片区 —— 需求要求展示汇总数据
2. 表格去掉批量操作 —— 该业务无批量操作场景
```

**任何一条差异都要能被需求解释**。解释不了的差异就是跑偏，应当改回基准页写法。

## 给非前端的 5 秒快速验收

不用读代码，只看四处：

1. **颜色**：页面上有没有突兀的纯白块或纯灰块。
2. **间距**：搜索框、按钮、表格之间的空隙是否和别的页面一样松紧。
3. **按钮**：长相、圆角、大小是否和别的页面一致，有没有出现“另一个系统”的按钮。
4. **表格**：工具栏和分页是否还在，列设置按钮是否可用。

四处都对，基本就没跑偏。
