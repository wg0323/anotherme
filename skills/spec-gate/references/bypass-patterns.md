# 常见绕行模式

六种模式来自真实翻车记录。每种给「表现 → 检测问句 → 正确动作」。交付前逐条自问，任何一条答不上来就回去补。

## BP-1 计划替代规范

**表现**：计划文档写得极细（连每个类、每段代码都有），于是把它当成唯一权威逐条照抄，全程没打开技能核对。

**检测问句**：本次改动里，有哪几处是我从计划抄的、却从没在技能里核对过的？

**正确动作**：计划是输入，技能是规范。计划与技能冲突走冲突停机；计划没提到的，按技能补。

## BP-2 静默降级

**表现**：给整条条款判“不适用”，判据是任务属性（存量工程、已批准设计、只改几行），而不是条款的触发条件。

**检测问句**：我判“不适用”的那些条款，判据指向的是触发条件，还是任务属性？

**正确动作**：回到条款看它的适用标记。标了〔通用〕的没有豁免空间；只有〔新建〕类条款能因“未新建工程”判不适用。

## BP-3 冲突自裁

**表现**：两条要求矛盾，自己选了一条，全程没告诉用户。

**检测问句**：有没有两个要求我看出了矛盾，选了其中一个却没上报？

**正确动作**：按 `common_rule` 的冲突停机格式列出 A 方、B 方、影响与候选，等用户裁决。自裁就是越权。

## BP-4 一次性绑定

**表现**：会话开头整理了技能清单，之后每个任务只更新 todo，不再检查“本阶段需要哪些技能”，直到开始写某类文件时才想起来。

**检测问句**：当前阶段的绑定表，是开场那张，还是本阶段重出的？

**正确动作**：阶段切换的信号是“产出对象类型变了”，不是“用户提了新需求”。写第一行新类型文件之前先重出绑定表。

## BP-5 测试即完成

**表现**：完成标准是“测试绿 + 计划复选框打勾”，台账里全是测试证据，没有一条规范自检证据。

**检测问句**：我的完成判据里，有没有“台账无待裁决项”这一条？

**正确动作**：完成定义是三条并列，不是一条。测试只证明功能，不证明合规。

## BP-6 长文本稀释

**表现**：技能正文很长，“强制”清单里混着“新建工程专有”和“通用规则”，模式匹配时把整块判成“不适用”。

**检测问句**：这条技能读完后，我能列出它全部的铁律编号吗？列不出说明被稀释了。

**正确动作**：按条款 ID 逐条对账，不按段落整体判断。技能正文过长时，把条款清单拉出来单独核对。
